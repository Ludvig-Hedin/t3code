# Summary of Changes

I made four targeted fixes to prevent thread freezing without breaking existing behavior:

## Changes Made

**1. Remove 60s timeout on critical orchestration RPCs** (`apps/web/src/wsRpcClient.ts`)

- `replayEvents()`, `getSnapshot()`, and `subscribeOrchestrationDomainEvents()` now use `Option.none()` (unbounded timeout)
- This prevents replay timeout on large threads after reconnect
- Terminal/file/other RPCs keep the 60s timeout

**2. More forgiving heartbeat** (`apps/web/src/wsRpcClient.ts`)

- Changed from 2×20s (40s) to 3×20s (60s) before connection reset
- Prevents premature disconnects during brief network hiccups

**3. Exponential backoff on subscription retry** (`apps/web/src/wsTransport.ts`)

- Changed from fixed 250ms retry to exponential: 250ms → 500ms → 1s → 2s → 5s (max)
- Added `onReconnect` callback hook for recovery

**4. Force replay after subscription reconnects** (`apps/web/src/routes/__root.tsx`)

- When subscription stream silently drops and reconnects, immediately trigger `recoverFromSequenceGap()`
- Don't wait for next event to detect gap
- This catches the "stream died while agent was thinking" case

- **Preserved all existing recovery logic** — no removal of safety mechanisms
